# 美团/点评 单商家团单抓取工具 — 设计文档

- 日期:2026-06-03
- 状态:已确认需求,待评审
- 用途:竞品 / 市场分析

## 1. 背景与目标

抓取美团某商家**全部团单**及每个团单的**完整画像**,用于竞品 / 市场分析。

每个团单需采集四类数据(用户已确认全部需要):

1. **团单详情**:套餐包含项目明细、现价、原价、适用门店、有效期、购买须知。
2. **履约 / 使用流程**:是否需预约、预约方式、到店核销流程、退款规则、使用时间限制等规则性文本。
3. **服务项目步骤**:针对服务类团单(美容/医美/按摩/家政),服务本身的流程步骤与时长。
4. **用户评价 / 销量**:已售数量、评分、评价文本。

## 2. 范围与边界

- **范围**:单商家、一次性快照。每次运行处理**一个**商家,跑一轮拿到全量数据。
- **不做**:定时监控、多商家批量调度、价格变化追踪。这些留待后续迭代(YAGNI)。
- **部署**:Cloudflare。定位为**按需工具** —— 输入一个商家页面 URL,跑一轮,产出并导出该商家全部团单数据。

## 3. 数据入口选择

**选定:大众点评 Web / H5。**

| 入口 | 数据完整度 | 反爬难度 | 结论 |
|---|---|---|---|
| 大众点评 Web/H5 | 团单明细、购买须知、退款规则、适用门店、评价最全,覆盖全部四类数据 | 字体加密 + 滑块验证码 | ✅ 选定 |
| 美团 App / 小程序 | 原始数据最全 | 接口 `mtgsig` 签名加密,需逆向 | ✗ 一次性需求工作量过大 |
| 美团 Web 团购页 | 仅部分品类(餐饮多、丽人/医美少) | 较低 | ✗ 覆盖不全 |

## 4. 抓取方案

**选定:混合法(Hybrid)。**

先用真实浏览器跑一遍建立会话(cookie / token)、过验证码,然后后续全部走 JSON 接口拉取列表 / 详情 / 评价。

理由:浏览器只在开头跑一次,验证码触发最少;主体数据走轻量 fetch,契合 Cloudflare Worker;每商家一轮会话,正好匹配"单商家一次性"。

被否方案:纯浏览器渲染(慢、资源重)、纯接口回放(逆向成本高、签名轮换即失效)。

## 5. Cloudflare 部署约束(关键)

1. Workers 跑不了普通 headless Chrome → 使用官方 **Browser Rendering(Puppeteer 绑定)**。
2. Cloudflare 出口为数据中心 IP,点评/美团风控敏感 → **代理策略:先裸跑,触发风控再接住宅/4G 代理**(已确认)。验证码触发视为已知风险。
3. Workers 有 CPU 时间 / 子请求数限制 → 抓取分步执行,必要时用 Queues 拆分;详情/评价请求加限速 + 并发上限。

## 6. 架构(分层)

```
[输入商家URL]
      │
┌─────▼──────────────────────────────────────────┐
│  API/编排层  (Cloudflare Worker, TypeScript)     │  建 job、调度、返回结果/状态
└─────┬──────────────────────────────────────────┘
      │
┌─────▼──────────────┐   ┌──────────────────────┐
│ 会话引导层          │   │ 接口抓取层            │
│ Browser Rendering   │──▶│ Worker fetch          │
│ Puppeteer 打开商家页 │   │ 列表→详情→规则→评价   │
│ 过滑块、取cookie/token│  │ (限速+并发上限)       │
│ (可选挂代理)        │   └─────────┬────────────┘
└────────────────────┘             │
                          ┌────────▼────────┐
                          │ 解析层           │  字体解密 + 字段归一化
                          └────────┬────────┘
                                   │
                    ┌──────────────▼─────────────────┐
                    │ 存储: D1(结构化) + R2(原始/字体/截图) │
                    └──────────────┬─────────────────┘
                                   │
                          [导出 Excel/CSV]
```

### 组件职责

- **API/编排层(Worker)**:接收商家 URL,创建并跟踪 job,串联各层,返回状态与导出文件。
- **会话引导层(Browser Rendering)**:Puppeteer 打开商家页,完成验证码(半自动,见 §8),提取 cookie / token / 必要签名参数。
- **接口抓取层(Worker fetch)**:用会话凭证依次调用「商家团单列表 → 每个团单详情 → 购买须知/规则 → 评价」接口,带限速与并发上限。
- **解析层**:字体解密(见 §7)、字段归一化映射到数据模型。
- **存储层**:D1 存结构化数据;R2 存原始响应、字体文件、验证码截图以便复查。
- **导出**:从 D1 生成 Excel/CSV(已确认仅此格式)。

## 7. 数据模型(D1)

- `merchant`:id, shop_uuid, name, category, address, city, source_url, scraped_at
- `deal`(团单):id, merchant_id, title, price, market_price, sales_count, valid_from, valid_to, category, raw_json
- `deal_item`(套餐明细/服务步骤):id, deal_id, name, qty, spec, step_order, duration —— 覆盖"服务项目步骤"
- `deal_rule`(购买须知/履约):id, deal_id, rule_type(预约方式/退款规则/使用时间/适用门店/…), text —— 覆盖"履约/使用流程"
- `review`:id, deal_id, merchant_id, rating, text, user_masked, review_date
- `job`:id, merchant_url, status, started_at, finished_at, error, stats_json

幂等:job 可重跑,`deal` 等按业务主键 upsert。

## 8. 关键设计点

- **字体解密**:每次抓取**动态下载**当前自定义字体文件,建立 glyph→字符映射还原数字/文字,**绝不硬编码**(字体随时变更)。字体文件存 R2 备查。
- **验证码处理:半自动·人工介入(已确认)**。触发时把滑块/截图存 R2 并暴露给操作者手动处理,job 进入 `awaiting_human` 状态;不依赖第三方打码平台。
- **会话复用**:浏览器开头跑一次取 session,主体走 JSON 接口,最小化验证码触发。
- **限速/风控兜底**:请求加间隔 + 并发上限;触发风控 → 重试降速,持续失败标记 job 需介入;接口签名失效 → 记录并提示重新逆向。

## 9. 侦察前置(实现第 0 步,必做)

混合法成败取决于接口结构,实现前必须手动抓包大众点评商家 H5 页确认:

1. 商家 → 团单列表 接口的 URL / 参数 / 签名字段。
2. 团单详情、购买须知、评价 接口的 URL / 参数。
3. 字体加密涉及哪些字段、字体文件位置。
4. 验证码触发条件。

此步骤产出会回填到实现计划,作为接口抓取层与解析层的依据。

## 10. 错误处理

- 验证码/风控触发 → 重试 + 降速;失败转 `awaiting_human`。
- 接口签名失效 → job 失败并记录,提示更新逆向。
- 字体文件变更 → 动态下载重建映射,不受影响。
- job 可重跑,按业务主键 upsert,保证幂等。

## 11. 测试策略

- 录制真实接口响应做解析层单测。
- 录制字体文件做字体解密单测。
- 一个已知商家做端到端 fixture。
- 风控/验证码路径用 mock 覆盖状态流转。

## 12. 合规

- 仅抓取公开数据,低频 + 限速。
- 评价中的用户昵称等**脱敏存储**(`user_masked`)。
- 用途限定竞品分析。
- 注意美团/点评 ToS 限制,控制请求频率以降低影响。

## 13. 技术栈

- Cloudflare Workers(TypeScript)+ Browser Rendering 绑定 + D1 + R2 +(可选)Queues。
- 可选外部依赖:住宅/4G 代理服务(仅在裸跑被风控后接入)。

## 14. 待后续迭代(本期不做)

- 定时监控 / 价格趋势追踪。
- 多商家批量调度 + 任务队列 + 代理池。
- 全自动验证码(打码平台)。
